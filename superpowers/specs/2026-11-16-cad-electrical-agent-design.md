# 设计文档:CAD 电气深化设计 Agent(goose 发行版)— 2026-11-16

状态:待业主批准 | 编写:ZCode(brainstorming 流程) | 环境:Windows 10 19044 x64,中文

## 1. 意图与动机(为什么做)

用户是电气设计师,日常从暖通专业接收 CAD 图纸,做机电/电气深化设计:审图清点、图纸净化、命名参数核对、配电干线规划、桥架走向。这条流水线重复度高、规则明确、以现行国家规范为硬约束,适合交给 agent 半自动化执行。目标形态:**一个 Windows 安装包**,装完即用;用户用自然语言驱动,agent 在用户的 AutoCAD 里实际画图/改图,并产出 Excel/Word 交付物。

## 2. 目标 / 非目标 / 反目标

**目标**
1. 支持下列 7 步工作流(经规范核对修订,2026-11-16):
   - S1 接图归档:暖通 CAD 图纸接收,原图存档为原始依据
   - S2 审图建档:设计说明核对(读 docx/pdf)、机电设备清点(按块统计)、图框及名称核对 → 产出**资产登记表 .xlsx**
   - S3 供电条件征询:进线电源/当地供电要求确认(新增步,核对正规深化流程后补充;信息来自用户提供或项目资料)
   - S4 图纸净化:在副本上清理无关图层(保留机电+基建;清除/隐藏暖通管道、装修、吊顶等)→ 产出净化 DWG
   - S5 命名参数核对:门/墙/房间功能名、设备标识符命名规则、设备标准参数 → 产出核对报告 .docx
   - S6 配电规划:按楼层/区域规划电柜位置(交互确认)、竖向配电干线图;明确架空区/多电井约束;楼层负荷汇总;室内优先 BV 2.5,按载流量规划回路数(GB/T 16895.15 表 × 敷设方式校正;GB 50054 保护配合;照明 C10~C16,插座 C16+30mA RCD)
   - S7 桥架走向:GB 50168-2018 全程约束(5.2.9 弯曲半径、5.2.10 全长接地、6.1.6 支点间距、6.1.7 最小弯曲半径表)+ GB 51348-2019 布线设计
2. 规范网关:任何设计动作执行前,按标准号联网核实现行版本 → 本地缓存带版本戳;**查不到即拒绝执行并报告缺哪本**(用户硬性要求)
3. 单安装包交付,装完即用;全部自研部分为 Rust
4. goose 原装使用(Apache-2.0,附 LICENSE 与 "based on goose" 署名,不用其名与 logo 作产品名)

**非目标(第一阶段不做)**
- 结构/给排水/暖通深化;BIM 三维;AutoCAD LT 支持;goose 内核改造;多平台(macOS/Linux);团队协作/服务端

**反目标(出现即失败)**
- 无现行规范依据的自动出图(规范网关必须先行)
- 绕过/修补软件授权机制
- 在原图上直接动手(必须副本操作)

## 3. 约束

| 约束 | 内容 |
|------|------|

## 4. 方案比选(2026-11-16 定案)

| 方案 | 内容 | 结论 |
|------|------|------|
| 原案:fork oh-my-pi | TS 内核 + Rust natives | **否**——不符合"纯 Rust"要求 |
| B:fork codex-rs 深度定制 | Rust 编码特化 agent 为基座 | 否——编码定位不如通用自动化贴合;维护 fork 成本高;将来做独立产品再启用 |
| C:Rig/Swiftide + rmcp 自建 | 全自研 agent harness | 否——会话/权限/TUI/skills 加载全自造,工作量最大 |
| **A(选定):goose 原装 + 自研 Rust MCP + 组件编排** | agent 零 fork,价值全在自研 MCP server 与 skills | **选 A**。goose 纯 Rust、Apache-2.0、MCP/skills 原生、recipes 适合批量任务;官方支持 Custom Distributions |

组件选型(2026-11-16 核实):
- **autocad-mcp-pro**(MIT,Python,247 工具,COM+ezdxf 双引擎):CAD 工具主力;`CAD_PROGID` 默认值与用户环境匹配;电气符号它没有(IEC 60617 在其 1.7 路线),电气知识全部自建 skills。以 python-build-standalone + 离线 wheels 内嵌;用 `TOOL_PACKS=core,plant,settings` 裁剪 token(全量 242 工具≈84k tokens)
- **anydoc**(MIT,纯 Rust crate):Office/PDF/CSV→Markdown,读侧内嵌进自研 server
- **agent-desktop**(Apache-2.0,Rust):UI Automation 兜底(对话框/打印窗口),MCP 模式,默认关闭
- **Office 写入**:`rust_xlsxwriter`(xlsx)+ `docx-rs`(docx)纯 Rust 生成;改既有 Office 文件走 COM(目标机 Office 2016 + WPS COM 均已注册)
- **DXF/DWG 读写**:`acadrust` 0.6 原生 DWG/DXF 文件级批处理(failsafe;Unknown 按 dxf_name 保留身份);LibreDWG 仅作外部进程兜底,GPL 不链接进 acad-mcp

## 5. 系统结构(已定)

```
安装包(Inno Setup exe;同目录结构兼出 portable zip,~150-200MB)
├─ goose + 预配置:注册下列 MCP servers、skills 目录、provider 引导
├─ acad-mcp.exe(自研 Rust,rmcp):
│   ├─ COM 桥 → 运行中 AutoCAD:开图/存副本/画线画块/插符号/查实体/改图层/跑 LISP/出图
│   ├─ DXF 文件级:无头批处理(读图/清点/图层分析)
│   ├─ anydoc 内嵌:读 docx/pdf/xlsx/csv 设计资料
│   ├─ Office 写入:xlsx(资产表/材料表)+ docx(核对报告);Office COM 改既有文件
│   └─ 规范网关:标准号→联网核版→缓存→阻断判定(亦暴露为 MCP 工具)
├─ python-embedded + autocad-mcp-pro 离线 wheels(TOOL_PACKS 裁剪)
├─ agent-desktop.exe(MCP 模式,默认关)
└─ skills/电气领域包(自研,SKILL.md):
    ├─ 工作流编排 skill(S1-S7 主管线)
    ├─ 图层规范 skill(保留/清除映射,从样本图纸归纳,随项目可增)
    ├─ 命名规范 skill(设备标识符/图框规则)
    ├─ 配电计算 skill(BV 2.5 优先、载流量查表流程、回路划分、负荷汇总;数值一律经规范网关取)
    ├─ 桥架规范 skill(GB 50168-2018 条款映射)
    └─ 符号块库(dwg/dxf)+ 图框模板(dwt)
```

工具面裁剪原则:自研 server 工具名面向电气任务语义(如 `count_blocks`、`plan_circuits`),不暴露 COM 细节;goose 的 skills 负责把 7 步流程串成可执行路径。

## 6. 规范网关(核心机制,已定)

1. skills 与用户指令只引用**标准号**(如 GB 50168-2018),数值/条文不硬编码
2. 网关按标准号联网查现行有效版本(源:国家标准全文公开系统等,源列表实施期定,多源兜底)
3. 命中 → 本地缓存(标准号+版本号+抓取日期戳)→ 设计动作放行
4. 未命中/版本过期 → **拒绝执行该动作**,报告缺失标准号;用户可放行降级为"仅引用已缓存版本"并留痕
5. 桥架等双标准场景(GB 50168 + GB 51348)逐本核验,缺一即阻断对应动作

### 7.1 施工者审查后由本方拍板的四项(2026-11-16,施工者问 Q4/Q5/Q6a/Q8)

1. **无头批处理路线按 AutoCAD 版本切换**:2014 精简版无 accoreconsole 才走 COM 后台实例;业主装正版完整版(2024/2025)后自带 accoreconsole,**无头批处理改为 accoreconsole 优先**,COM 后台实例降为兜底
2. **规范网关门禁范围**:只门禁"引用规范条文/数值的动作"(S6 计算、S7 桥架、出图中引用标准数值处)。S4 净化依据图层规则、S5 核对依据命名规则,均非国标数值依据,不受门禁(否则流水线被堵死);但两步中凡引用标准处仍走网关
3. **离线首装策略**:安装包预置基线缓存(实施期已核验版本的常用标准:GB 50168-2018、GB 50054-2011、GB 51348-2019、**GB/T 16895.15-2023**(2026-11-16 核实为现行版,替代 2002 版)、JGJ 242-2011);目标机离线时,规范依赖动作按业主硬性要求**全阻断**。文本获取模式(2026-11-16 业主表态购买):业主购买正式文本 → 本地结构化缓存;联网侧用国家标准全文公开系统(openstd.samr.gov.cn)免费核验现行版本。详见当日采购清单(对话记录)
4. **入口形态**:goose Desktop 优先(用户是设计师非程序员),CLI/TUI 兜底;界面中文化尽力而为(受 goose 现有本地化程度限制,skills 全部中文)

### 8.1 施工者审查提出的问题——**业主已全部回答(2026-11-16),据此定案**

1. **规范文本获取模式**:业主答复"我建立好知识库,对接"→ 网关定型为:**业主自建规范知识库,agent 侧实现 KB 适配器**(本地目录契约:M2 计划中定义,预计为 `标准号/版本/内容文件 + 索引清单` 结构,兼容 md/txt/pdf);联网侧(openstd)仅负责核验知识库中版本是否现行,现行性不符即阻断
2. **暖通来图技术栈**:业主已安装**天正电气**→ 按定案执行代理实体降级读取;⚠️ 事实澄清:天正电气以 AutoCAD 为宿主,**当前 AutoCAD 2014 损坏则天正电气同样不可用**——采购正版 AutoCAD 后两者一并恢复;符号块库/模板基线按天正环境归纳
3. **S6/S7 自动化程度**:业主选定 **C:agent 提案 → 确认 → 成图(半自动)**;全自动寻路算法不做
4. **负荷参数口径**:业主认可《工业与民用供配电设计手册(第四版)》数值,按"权威工具书"入库标来源,不经国标网关
5. **命名核对基准**:无院标 → 以雁能1# 样本归纳命名规则为基准,规则表经业主确认后固化
6. **分发范围**:仅业主本人使用 → LibreDWG 以外部工具调用无分发义务;无需代码签名;安装包不分发
